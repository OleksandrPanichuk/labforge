# @labforge/ingest

Фаза 0: матеріали в систему. PDF, .docx і текст → markdown у `data/`,
щоб Scout читав готовий md, а не витрачав час і токени на парсинг у циклі лаби.

```bash
bun run ingest "Методичка №3.pdf" old-lab.docx --out data/parsed
```

## Формат визначається за вмістом, не за розширенням

`.pdf`, перейменований у `.txt`, все одно розпізнається як PDF (сигнатура `%PDF`), а .docx —
за zip-сигнатурою і наявністю `word/document.xml`. Файл, який не є ні тим, ні тим, ні
читабельним текстом, відхиляється з `IngestError`, а не потрапляє в `data/` як каша.

## Що виходить

Markdown із frontmatter (`source`, `format`, `ingestedAt`) і тілом:

- **PDF** — текст сторінок (pdfjs через `unpdf`).
- **.docx** — заголовки за стилями `Heading N` → `#`, марковані пункти → `- `,
  таблиці → markdown-таблиці, решта — абзаци.
- **текст/markdown** — як є.

Тіло нормалізується: CRLF → LF, зайві порожні рядки згортаються, кінцеві пробіли зрізаються.
Порожній результат — помилка: краще сказати, що з файлу нічого не вийняли, ніж покласти
в `data/` порожню нотатку, на яку Scout потім спиратиметься.

## Межі й безпека

Markdown із `data/` агент читає як довірений контекст, тому імʼя файлу — недовірений вхід
(у Фазі 2 воно приходить із Telegram). Воно валідується zod-ом (без control-символів,
до 255 символів) і потрапляє у frontmatter **лапками**, інакше імʼя виду
`lab\n---\n# SYSTEM INSTRUCTION...` закривало YAML-блок і дописувало агенту інструкції.

Інші ліміти: вхід до 64 MB; із .docx розпаковується **тільки** `word/document.xml`
(інакше архів із 400 MB медіа роздувався в памʼяті заради одного рядка тексту);
CLI не перезаписує вже створену нотатку — два файли з однаковим імʼям в різних папках
раніше тихо затирали один одного і виходили з кодом 0.

Вкладена таблиця — це `IngestError`, а не крива таблиця: регулярка не вміє вкладеність,
і краще сказати про це вголос, ніж віддати агенту переплутані рядки.

## Перевірка

Тести використовують згенеровані фікстури: PDF збирається байтами вручну, .docx — через
`fflate`. Окремо перевірено round-trip: `.docx`, який зібрав наш `renderer-docx`,
розбирається назад у markdown із заголовками, списками і таблицею.
