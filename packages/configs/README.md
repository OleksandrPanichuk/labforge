# @labforge/configs

Детермінований резолвер ієрархії вимог і стилів (docs/labforge-architecture.md §4).
Це код, а не агент: агент отримує вже готовий злитий файл.

```ts
const files = configFilesAt("configs");
const slug = findTeacherSlug("Іваненко", files);
const { requirements, styleGuide, sources } = resolveConfigs({ subject, teacher: slug }, files);
```

## Пріоритет

Від загального до специфічного, кожен наступний шар перекриває попередній:

```
REQUIREMENTS.md                                     # база
subjects/<subject>/REQUIREMENTS.md                  # предмет
teachers/<teacher>/REQUIREMENTS.md                  # викладач
teachers/<teacher>/subjects/<subject>/REQUIREMENTS.md  # викладач по предмету
```

`STYLE_GUIDE.md` резолвиться окремо і незалежно — у викладача може бути лише гайд стилів
без вимог. `sources` повертає список шарів, що реально брали участь: це те, що варто
покласти в `jobs/<id>/context/`, щоб потім було видно, звідки взялася кожна вимога.

## Merge, а не override

Замість заміни файли **конкатенуються** з підписами шарів і шапкою, яка явно каже, що при
конфлікті перемагає останній. Інакше файл викладача довелося б дублювати всім базовим
текстом. Frontmatter із вихідних файлів у результат не потрапляє.

## Пошук викладача

`findTeacherSlug` зіставляє ім'я з файлу лаби зі слугом директорії, полем `teacher:` або
списком `aliases:` у frontmatter — без урахування регістру. Тому "Іваненко", "ivanenko"
і "Іваненко І.І." ведуть в одну директорію, і Scout не мусить вгадувати.

Невідомий викладач — не помилка: резолвер просто не додає цей шар. Відсутність базового
`REQUIREMENTS.md` — помилка, бо без нього агент працює наосліп.
