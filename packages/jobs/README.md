# @labforge/jobs

Робоча директорія лаби і checkpoint — те, на чому тримається інваріант 5:
кожен стан стейт-машини має бути rerunnable з файлів, а не з памʼяті сесії.

```ts
const store = createJobStore("jobs");
const job = store.createJob("job_42");

job.advanceTo("SOLVE");
```

## Структура job-директорії

```
jobs/<id>/
  src/ cells/ artifacts/ runs/ context/ review/
  checkpoint.json
  report.ir.json
```

Усі директорії створюються одразу — зокрема `artifacts/`. Якщо її не створити, Docker
змонтує її сам і на частині рантаймів вона буде root-owned, а cell під uid 1000 не зможе
туди писати (див. README пакета sandbox).

## Checkpoint

Zod-схема з переліком станів із CLAUDE.md, лічильниками входжень (`cycles`) — на них
спираються стоп-правила рев'ю-циклів — і session id-ами для resume після rate limit.
Побитий або несхемний checkpoint — це `JobStoreError`, а не тихо проігнорований файл:
краще впасти, ніж почати стан із порожньої памʼяті.

## Довговічність

`checkpoint.json` пишеться атомарно (temp + fsync + rename), бо це єдина копія стану job-и,
а ноут вимикають щовечора. Якщо робоча копія все одно побилась — читання підхоплює останній
закомічений checkpoint із git, і job продовжується замість того, щоб застрягти назавжди.
Помилка лишається тільки коли нема ні файлу, ні історії.

`advanceTo` тримає lock-файл на весь цикл read-modify-write-commit. Без нього два процеси
(наприклад revision і watchdog) переплітали записи і лишали checkpoint нечитабельним; тепер
другий процес отримує `JobStoreError`, а не пошкоджує стан. Якщо коміт впав — checkpoint
відкочується на попередній, щоб файл і історія не розходились.

## Git-ізоляція

Усі git-виклики йдуть із явними `--git-dir`/`--work-tree`. Інакше job-директорія без
власного `.git` (наприклад відновлена з бекапу) знайшла б **батьківський** репозиторій вгору
по дереву, і `git add -A` замітав би у коміт чужу незакомічену роботу. `openJob` до того ж
переініціалізує репозиторій, якщо його нема. Глобальні `core.excludesFile`, `core.hooksPath`
і `init.templateDir` занулені — інакше чужий глобальний ignore тихо викидав би `artifacts/`
чи `runs/*.log` з історії, тобто саме ті докази, заради яких інваріант 5 існує.

## Цикли і зупинка

`cycles` рахує **повернення** в стан, а не входження: rerun того самого стану після падіння
і пауза через ліміт циклу не витрачають. Інакше стоп-правило "макс 3 цикли" спрацьовувало б
після одного справжнього рев'ю на ноуті, який щоночі вимикають.

Термінальні стани (`DONE`, `CANCELLED`) — справді термінальні: `advanceTo` з них кидає.
Повна таблиця переходів живе у стейт-машині core; тут лише те, що робить стан незворотним.

## advanceTo

`advanceTo(state)` робить обидві половини інваріанта 5 одним викликом: пише checkpoint
і комітить job-директорію. Тому історія станів завжди є, і відкат до попереднього стану —
це звичайний git. Коміти йдуть під власною ідентичністю (`LabForge <labforge@localhost>`),
щоб не залежати від того, чи налаштований git на машині.
