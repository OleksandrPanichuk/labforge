# @labforge/agent

Реалізація порту `AgentRunner` зі стейт-машини через Claude Agent SDK. Тут — усе, що знає
про LLM; орchestrator не знає нічого.

## Що робить

- **Промпт за станом**: `SOLVE` → `agents/scout-solver.md`, `CODE_REVIEW` → `reviewer-fixer` і т.д.
  Стан без агента (`RESOLVE`, `BUILD`, `INGEST`, `HUMAN_REVIEW`) — це помилка, а не тихий no-op:
  такі стани виконує детермінований код, і плутанина тут ламала б інваріант 1.
- **Набір тулів береться з frontmatter промпту**, не з коду, і передається в SDK як `tools`
  (саме він **обмежує** набір) разом з `allowedTools` (він лише знімає підтвердження).
  Спайк цю різницю не показав: `Write` тоді не спрацював просто тому, що не був
  auto-allowed. Але без `settingSources: []` сесія підхопила б `~/.claude/settings.json`
  користувача — а там у `permissions.allow` цілком можуть лежати `Bash(...)`-правила, і
  агент лаби отримав би готовий дозвіл виконувати код на хості повз `run_in_sandbox`.
  Тому: `tools` + `settingSources: []`. Промпт без `allowedTools` — помилка, а не «дозволити все».
- **Два кастомні тули** (in-process MCP): `ask_user` — записує питання і просить агента
  зупинитись (сесія завершується, воркер вільний); `run_in_sandbox` — єдиний шлях до Docker,
  команду будує runtime-профіль мови лаби, тому агент не обирає ні образ, ні інтерпретатор.
- **Мапінг результату**: `rate_limit_event` зі статусом `rejected` → `rate_limited` + `resumeAt`
  (час із SDK, у ISO); виклик `ask_user` → `needs_user`; помилка → `failed`; інакше `completed`.
- **Кінець сесії перевіряється**: SDK може завершитись `error_max_turns`,
  `error_during_execution` чи `is_error: true` — усе це `failed`, а не `completed`. Інакше
  машина пішла б далі зі стану, який нічого не зробив.
- **Findings** після рев'ю читаються з `review/findings.json` (код) або
  `review/report-findings.json` (звіт). Закриті (`fixed`/`wontfix`) не рахуються, а
  нечитабельний файл — це `failed`. Так само і **відсутній** файл після рев'ю: мовчазний
  «нуль findings» проскочив би рев'ю-цикл, а це найімовірніший збій (агент упав, Write не
  дозволили, записав не туди). Для FIX/IR_FIX відсутність файлу нормальна.

- **Плейсхолдери промпту заповнюються всі**: `{{prevFindings}}` бере findings попереднього
  раунду з checkpoint, `{{userComment}}` — з revision-контексту. Незаповнений плейсхолдер —
  виняток, бо інакше агент отримував би текст `Коментар: {{userComment}}` і працював наосліп.

- **Протухла сесія не вбиває job**: якщо resume не спрацював, стан переганяється ще раз
  без `resume` — рівно те, що вимагає CLAUDE.md.

## Чому SDK за портом

`Session` — це порт; `claudeSession()` — його реалізація на SDK. Тому вся логіка адаптера
(вибір промпту, підстановки, мапінг результату, findings) тестується без жодного виклику
моделі, а тонкий шар навколо `query()` лишається єдиним неперевіреним тестами місцем.

Сесію повертає `sessionId`, і стейт-машина передає його назад у `resumeSessionId` —
спайком перевірено, що SDK відновлює сесію навіть з іншого процесу.
