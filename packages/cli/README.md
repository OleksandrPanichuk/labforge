# @labforge/cli

Точка входу Фази 1: лаба від файлу завдання до `.docx`, без веба.

```bash
bun run lab:run data/lab-3.md --subject numeric-methods --teacher Іваненко --language python
```

Результат — `jobs/<id>/` з `src/`, `cells/`, resolved `report.ir.json`, `report.docx`
і git-історією по одному коміту на стан.

## Диспетчер

Стани діляться на два види, і це прямо інваріант 4:

| Стан | Хто виконує |
|---|---|
| `INGEST` | код: кладе завдання в job (конвертує PDF/docx), резолвить configs у `context/` |
| `RESOLVE` | код: cells у sandbox + валідація, записує resolved IR — **без** docx |
| `BUILD` | код: рендер docx з уже порахованого IR, **не перезапускаючи** cells |
| решта | агент через `@labforge/agent` |

LLM ніколи не торкається resolve і build — інакше число у звіті могло б з'явитися не з коду.
RESOLVE і BUILD розділені навмисно: інакше BUILD після рев'ю людини перезапустив би cells і
міг покласти у фінальний docx **інші числа**, ніж ті, які людина щойно погодила (інваріант 2).
І docx не з'являється до рев'ю — «файл є» не має означати «звіт готовий».

Помилка pipeline не вбиває job: стадія `resolve` повертає job у `FIX` (код cell зламаний),
решта стадій — в `IR_FIX` (зламаний документ), і все це під тим самим лімітом у 3 цикли.
Стан, який нікому не належить, повертає `failed` з поясненням, а не кидає виняток посеред
машини.

## Зупинка на людині

За замовчуванням прогін зупиняється перед `HUMAN_REVIEW`: далі потрібне превʼю (Фаза 3).
`--stop-before` дозволяє зупинитись раніше, наприклад щоб подивитись на код після `SOLVE`.

Коди виходу: `0` — дійшли до кінця, `1` — job упав, `2` — job на паузі. Пауза не 0, бо для
черги чи CI «вийшли нулем і docx нема» виглядало б як успіх. У лог іде питання агента,
час зняття ліміту, шлях job-директорії і — на успіху — шлях до docx.

Питання студенту наразі можна відповісти лише правкою файлів у job-директорії: каналу
відповіді ще нема, він з'явиться разом із TG-ботом (Фаза 2).

## Перевірка

Наскрізний тест ганяє **всю** машину на справжньому Docker зі скриптованим агентом замість
LLM: завдання → context → src/ → cells/ → resolved values → docx → checkpoint-и в git.
Це і є критерій приймання Фази 1 мінус сам LLM.
